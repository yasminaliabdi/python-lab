Reflection: Branches and Pull Requests

Branches and pull requests are essential tools for collaborative software development. Instead of committing directly to the main branch, developers create separate branches to work on new features, bug fixes, or experiments. This isolates their changes so that the main branch remains stable and deployable at all times. Once the work is complete, the developer opens a pull request to propose merging their changes into main.

During a code review on a pull request, other team members examine the code for correctness, readability, and adherence to coding standards. They can leave comments, suggest improvements, and discuss potential issues. The pull request also runs automated tests to ensure the new code doesn't break existing functionality. Once all feedback is addressed and tests pass, a reviewer approves the pull request and merges it into main. This process ensures code quality, catches bugs early, and maintains a clean, reliable codebase.
